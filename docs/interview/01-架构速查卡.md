# Grodex 面试速查卡（5 分钟叙事版）

> 目标：面试官 30 秒进入状态，5 分钟建立"这个人真的懂"的印象。
> 核心原则：**三层叙事 + 一个主打深度**，剩下的让面试官挑。

---

## 开场一句话（30 秒）

> "我用 Rust 写了一个 AI 编程代理（80k 行 / 21 个 crate / 858 测试），
> 核心特性是**崩溃恢复**——它把所有动作记入一个只追加的 journal，
> 任何时刻被 kill 都能精确恢复到中断点。
> 现在我们的对话就跑在它里面。"

---

## 三层叙事（讲 2-3 分钟，配下图）

```
┌─────────────────────────────────────────────────┐
│ 第三层 扩展：subagent(子代理) / memory(FTS5) /    │
│         mcp(外部工具) / ACP(TUI-桌面协议)         │
├─────────────────────────────────────────────────┤
│ 第二层 安全：permission(策略编译+审批工单) /       │
│         sandbox(Seatbelt内核强制+外置supervisor) /│
│         auth(凭证代理+租约+OAuth)                 │
├─────────────────────────────────────────────────┤
│ 第一层 核心：loop(主循环) / rollout(journal+不变量) │
│         / tools(7工具) / provider+sampler(模型)   │
└─────────────────────────────────────────────────┘
```

- **第一层（核心）**：agent 的"大脑 + 记忆"。主循环驱动一次 Turn，每次工具调用先写 journal 再执行（WAL 思想）。
- **第二层（安全）**：工具不是随便调的。策略文件编译成决策，高风险操作生成审批工单；执行时被内核沙箱（macOS Seatbelt）强制限制。
- **第三层（扩展）**：跑不动了就派子代理（邮箱/调度/工作区），记不住了就用 SQLite FTS5，要接外部服务就走 MCP/ACP。

> 讲完主动说："**我最想深挖的是第一层的崩溃恢复**，它是整个系统的骨架。"

## 主打深度：崩溃恢复（面试官同意后讲 3-5 分钟）

### 问题
AI agent 一跑几小时，模型中途崩了/断网/被 kill，怎么恢复？

### 方案（write-ahead journal）
1. 每个事件（消息、工具调用、工具结果、提交）**先追加进 journal 并 fsync，再执行**——journal 是唯一事实源，内存状态只是它的投影。
2. 工具调用有完整生命周期事件（started → delta* → completed/aborted），中断时状态可判定。
3. `grodex resume <sid>`：读 journal → 重放 → 状态机恢复到中断前一刻，**模型不会"失忆"**（早期的双写 bug 就是 chat_state 与 journal 不同步，后来统一为 journal 单源）。
4. 17 条运行时不变量（工具调用生命周期、step 单调性、压缩原子性……）在测试中硬断言；有随机中断的编排测试验证恢复。

### 证据（主动展示）
- `grodex inspect <sid>`：结构化列出每个事件（seq、类型、时间戳、载荷摘要）
- `grodex replay <sid>`：纯重放，不调模型
- 现场 kill -9 演示（见 demo 脚本）

## 三个备用深挖点（面试官不选崩溃恢复时）

| 深挖点 | 30 秒卖点 | 关键文件 |
|---|---|---|
| **Seatbelt 沙箱** | macOS 内核级强制（不是 chroot 模拟），fail-closed：未声明路径默认拒绝；supervisor 是独立外置进程，agent 崩了沙箱不受影响 | `grodex-sandbox/` |
| **权限系统** | 策略文件(rule→facts→decision)编译 + 审批工单(lease 一次性) + narrow 授权（"只允许这一次、这个文件"） | `grodex-permission/` |
| **凭证代理** | 模型永远看不到真实密钥；按 server 发租约；OAuth 全流程(PKCE)+单飞刷新+熔断器 | `grodex-auth/` |

## 21 个 crate 一句话表（被追问"为什么这么多"时用）

| crate | 一句话 |
|---|---|
| `core` | 领域类型与事件定义 |
| `rollout` | **journal、不变量、崩溃恢复（hero）** |
| `loop` | 主循环：Turn 编排、step、上下文投影、压缩 |
| `tools` | 7 个内置工具 + blob 大结果外置 + 原子写 |
| `permission` | 策略编译 + 审批工单状态机 |
| `sandbox` | Seatbelt 内核强制 + 外置 supervisor 进程 |
| `auth` | 凭证代理(文件存储 0600)、OAuth broker、租约 |
| `provider` | 模型路由、failover、lossiness 降级栅栏 |
| `sampler` | 采样 Actor、prompt caching、熔断器 |
| `prompt` | 指令发现(AGENTS.md)、prompt 装配、slash 注册表 |
| `config` | 8 模块：分层、合并、migration、trust、watcher |
| `capability` | 能力注册、revision 栅栏、deferred promotion、explain |
| `subagent` | 邮箱/调度/工作区、协作协议六件套 |
| `memory` | SQLite FTS5 10 表、vector、consolidation |
| `mcp` | MCP 客户端、OAuth 协调 |
| `protocol` | ACP：EventEnvelope、ResolveApproval、Resume+ACK |
| `tui` | 交互界面（10k 行） |
| `cli` | 命令装配：run/serve/resume/replay/inspect/dump/eval |
| `skills` | skill 清单/按需加载/信任 |
| `sandbox-types` / `auth-types` | 跨 crate 共享类型 |

### "为什么 21 个 crate？"（模型回答）
> "每个 crate 是一个编译期契约边界。Rust 的类型系统让跨边界改动必须同时改两端，
> 所以边界本身就是架构评审。代价是前期慢——但 25 轮迭代里从来没出现过
> '改 A 忘了 B' 的跨模块 bug，我认为这个成本花得值。
> 现在回头看，`loop`(14.7k) 和 `tui`(10k) 两个 crate 偏大，下一轮会拆。"

## 被问"和 Claude Code / Codex 比呢？"（诚实版）

> "产品功能上差很多：没有全文搜索工具、没有代码索引、TUI 和上下文优化都还初级。
> 但在**可靠性骨架**上我做了它们没有的东西：崩溃恢复、内核沙箱、凭证代理、
> 可审计的完整事件流——因为我的目标不是复制一个产品，
> 而是证明我能设计一个'出问题也不会数据损坏'的系统。
> 如果继续做，下一步我会补搜索和索引。"
