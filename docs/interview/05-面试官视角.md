# 面试官视角：听完 3 分钟介绍后他会怎么问

> 模拟对象：用过 Claude Code、做过分布式系统的资深工程师。
> 用途：预演最可能的追问路径，重点练"可靠性链"（Q3→Q2→Q6→Q5）。
> 原则：自己说出来的叫"已知边界"，被问出来才说的叫"隐瞒"。

---

## 面试官的思维模式

他会怀疑三件事：
1. **"崩了不丢"**——最漂亮，所以要最用力戳
2. **"858 测试全绿"**——数字越大越要验证是不是你自己写的
3. **"25 轮审计，没有跨模块回归"**——太完美了，完美得像包装过的

四条攻击线：**验证线（戳边界）→ 深度线（往下两层）→ 诚实线（找你没说的）→ 所有权线（判断是不是你写的）**。

---

## 第一轮：验证线（热身，但暗藏杀机）

### Q1. "每次事件都 fsync 吗？还是批量落盘？"
- 考察点：WAL 落盘语义。批量 = 丢窗口；逐个 = 慢。
- 追问链：*"fsync 只保证到内核。机器断电呢？"*
- 答题要点：诚实说明落盘语义 + 崩溃窗口 = 未开始执行的意图，而非已执行的后果。

### Q2. "journal 单文件吗？压缩写到一半又崩了呢？"
- 考察点：压缩原子性。
- 答题要点（30 秒版）："新段写入 + fsync + 原子切换指针；切换中崩溃回退旧段。这条本身就是一条不变量，有测试钉死。压缩是异步的，不阻塞模型响应。"

### Q3.（全场最危险）"exec 删了文件，结果写回 journal 前崩了。重放时这个 exec 是什么状态？"
- 考察点：**exactly-once vs at-least-once**。
- 真实答案：started 无 completed → 标 aborted → 模型重试 → **exec 可能重复执行**。不是 exactly-once，是"至少一次 + 告知重试"。
- ✅ 标准答案：
  > "工具副作用无法做到 exactly-once，这是所有 agent 的物理边界，不是我的实现缺陷。我的系统保证的是**状态一致性**：副作用发生没记录 = 重放后模型看到 aborted，由模型知情决定是否重试。journal 里保留完整事件，模型看得到'这个调用被中断过'。主流工具连这个都不保证——它们是黑盒。"
- ⚠️ 答不好，前面"崩了不丢"全部崩塌。这句必须先自己想清楚再说出去。

### Q4. "重放是确定性的吗？重放会重新调模型吗？"
- 答题要点："replay 纯重放不调模型，只重建状态；resume 在重放后继续调模型。两条命令分开。" 30 秒讲完，加分。

---

## 第二轮：深度线（往下挖两层）

### Q5. "17 条不变量，挑一条讲讲它防住了什么真实 bug。"
- ⚠️ 不要挑"写的时候就知道会崩"的（露馅）。**用双写失忆 bug 对应的"单一事实源"**：故事完整、真实、有周末修 bug 的细节。

### Q6.（地雷）"随机中断测试怎么注入？自己写的 fault injection 还是现成的？"
- ⚠️ 审计文档 30.3 写着"故障注入 7 点位崩溃测试——未完成"，你实际是随机化调度替代。**别撒谎，别含糊。**
- ✅ 标准答案：
  > "分层说：单元级我们做随机化调度，故意乱序触发事件；进程级故障注入（在压缩窗口、journal 切换点打断）我知道没做——这是审计文档里明确记着的未完成项，需要真机长链路才能闭环。我不装这个。"

### Q7. "沙箱里 symlink 指向 /etc 怎么办？你测过吗？"
- 答题要点："Seatbelt 常规路径行为我验证过；symlink 逃逸没有专项测试，这是开放问题。" **承认比嘴硬安全。**

### Q8. "凭证代理——模型看不到 key，那工具执行时怎么注入？进程内还是外置？"
- 考察点：安全边界是否真正闭合。答题要点：注入发生在凭证代理侧，模型/工具调用链只持有租约引用，真实密钥不出代理进程。

## 第三轮：诚实线（找你没说的）

### Q9. "没有搜索、没有索引，80k 行的项目里 agent 怎么找文件？"
- 答题要点："read 全量扫 + 模型推理，慢但可用。所以我的性能优化清单里 read 排第一——range-aware 读取 + 后台线程池，方案已经想好了。" 把缺口翻译成 roadmap。

### Q10. "你没提测试怎么写、上下文怎么管理。故意不说的？"
- 答题要点："我挑了差异点讲——崩溃恢复是别人没有的；上下文管理主流有成熟做法，我可以展开。" 有取舍的叙事 = 成熟工程师。

### Q11. "做了多久？"
- 真实数字：8/7-8/24，紧凑的 3 周全职强度。别虚报半年。
- 追问链：*"3 周八万行，平均一天四千行？"* → "设计先行 + 每轮审计迭代驱动，不是码字速度；前两周主要在写设计和修架构，最后一周完成度才冲上来。"

---

## 第四轮：所有权线（判断是不是你写的）

### Q12.（加分位）"git log 只有 15 个 commit，25 轮审计怎么对上的？"
- ✅ 标准答案："commit 是里程碑粒度；每轮细节在 task 目录的审计文档里，有日期、有失败、有教训。" ——**主动把审计文档指给他看**，这是你最强的所有权证据。AI 生成不了 25 轮带失败记录的自审。

### Q13. "现在让你在 invariants.rs 加一条新不变量，现场说说怎么设计。"
- 答题要点：方法论 = "从状态机迁移图上找没有被断言覆盖的转换边"——讲得出方法论才算写过。

### Q14. "AI 辅助写了多少？"
- ✅ 标准答案："日常用 Claude Code 当结对伙伴；架构、协议、journal 都是我设计的，每轮审计都是我写的。你现在随便指一行，我能讲它为什么这么写——'能判断 AI 写的对不对'本身就是这个项目的训练目标。"

## 最可能的 30 分钟走向

| 时间 | 环节 | 处境 |
|---|---|---|
| 0-3 分 | 你讲 3 分钟主版本 | 按 04 口语稿 |
| 3-12 分 | Q3→Q2→Q6→Q5（可靠性链） | 全场最险，提前背熟 |
| 12-18 分 | Q7→Q8→Q12（安全+所有权） | Q12 是加分位 |
| 18-25 分 | Q9→Q11→Q14（诚实+工作量） | 送分题，别嘴硬 |
| 25-30 分 | 你反问 | 问"你们 agent 怎么处理上下文爆炸" |

## 一句总结

面试官不会问"你的项目多好"，只会问"**你的项目哪里会坏**"。
提前想清楚三处"会坏"的地方——**exec 副作用重复、故障注入未覆盖、symlink 未测**——并且自己先说。
