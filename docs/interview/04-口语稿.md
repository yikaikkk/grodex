# Grodex 面试口语稿（三个版本）

> 用法：对着镜子/录音练 3 遍以上。30 秒版用于电梯场景；3 分钟版是主版本；
> 5 分钟版是面试官明显感兴趣时的扩展。
> 所有"你要是有兴趣……"结尾句必须真能现场做，否则别说。

---

## 一、30 秒电梯版

> "我用 Rust 从零写了一个 AI 编程代理——类似我自己版本的 Claude Code，八万行代码、21 个 crate、858 个测试全绿。它现在就跑在我这台电脑上，我日常调试代码经常用它。
>
> 但这个项目我最想讲的不是它能干活，而是它**崩了不丢**：所有动作先写进日志再执行，任何时候 kill 掉，重启后精确恢复，模型不失忆。为了这个，我定义了 17 条运行时不变量，用随机中断测试钉死。
>
> 整个项目是设计文档驱动的，13 份设计文档、25 轮自我审计。我对它的定位是：可靠性骨架比主流工具做得更深，产品功能还有差距。"

---

## 二、3 分钟主版本（面试现场版）

> "那我介绍一下。这个项目叫 Grodex，是我用 Rust 从零写的一个 AI 编程代理——你可以理解成'我自己的 Claude Code'。八万行代码，21 个 crate，858 个测试，全绿。它不是个 demo，我现在自己调试代码就经常跑它。
>
> 先说动机。市面上现成的 agent 很多，但它们对用户是个黑盒：跑着跑着挂了，你完全不知道它内部发生了什么，也没法恢复，只能从头再来。我做这个项目想挑战的问题就是——**能不能设计一个 agent，让它'出问题也不坏'**。所以我把重心从'能干活'挪到了'可靠'上。能干活谁都会调 API，可靠才是设计问题。
>
> 架构分三层，我快速讲。核心层是主循环加一个叫 rollout 的模块——这是整个系统的灵魂。它的核心思想是 **write-ahead journal**：模型的每一句话、每一次工具调用、每一个结果，都先追加写进一个只增不改的日志、落盘之后才执行。所以这个日志是**唯一的事实源**，内存里的所有状态都只是它的投影。这意味着什么？任何时刻 kill -9，重启后 resume，它通过重放日志，精确回到中断前那一瞬间——模型还记得自己刚才在干什么。为了把这条路走实，我定义了 17 条运行时不变量，比如工具调用生命周期必须合法、step 序号必须单调、压缩必须是原子的。这些不变量不是文档，是代码里硬断言，配合随机中断的编排测试来验证——测试的不是 happy path，是'在任意一点砍掉它，它都得活着回来'。
>
> 第二层是安全。工具不是随便调的：策略文件编译成决策，高风险操作生成审批工单，工单是一次性 lease，还能 narrow 到'只允许这一次、这一个文件'。执行时还有第二道防线——macOS 内核级的 Seatbelt 沙箱，fail-closed，没声明的路径直接 EPERM，不是 chroot 那种模拟的。另外凭证我做了个代理，模型从头到尾看不到真实的 API key。
>
> 第三层是扩展：任务太大就派子代理，有邮箱、调度、工作区；长期记忆走 SQLite FTS5；接外部工具走 MCP；TUI 界面走我自己设计的 ACP 协议。
>
> 再说说怎么做出来的，我觉得这跟代码同样重要。这是**设计文档驱动的开发**：13 份 V2 设计文档，25 轮迭代，每一轮结束都对照文档做差距审计，写成审计报告——这轮做了什么、测了什么、还剩什么、踩了什么坑。这个习惯让我在八万行、二十多个 crate 的规模下，几乎没有跨模块的回归。
>
> 最后说不足，我不藏着。全文搜索工具没有、代码索引没有，这些主流产品有我没有；工具执行性能还有优化空间。但这是我的取舍：先把正确性骨架做完——因为'能搜'是锦上添花，'崩了不丢'是地基。
>
> 如果你有兴趣，我可以现场演示崩溃恢复：开一个会话跑一半，kill 掉，resume 回来，它记得自己刚才在干嘛。或者你想深挖哪一层——journal、沙箱、权限，我都能展开。"

## 三、5 分钟扩展版（被追问时加的两块）

### 加块 1：一个真实 bug 的故事

> "我讲一个真实踩过的坑。早期 chat_state 和 journal 是两个事实源——journal 是权威的，但 chat_state 是模型真正读的。结果 resume 之后模型'失忆'，重放完了却不记得自己说过什么。修了一个周末，最后把 chat_state 删了，统一成 journal 单源。这个 bug 让我真正理解了'单一事实源'不是口号——两个源头，迟早会分叉，这不是概率问题，是时间问题。"

### 加块 2：测试策略

> "测试上我做三件事：第一，不变量断言——把'系统在任意崩溃点都合法'这件事变成可执行的测试；第二，随机化调度，故意乱序触发事件；第三，审计驱动——每轮迭代的测试数从 426 涨到 858，每涨一个数字都有对应的设计文档条款。"

---

## 四、说这段话的策略（为什么要这样讲）

1. **第一句就埋'崩了不丢'**——全场唯一要让面试官记住的句子。具体、反常识、可追问。
2. **先动机后设计**——"我想解决什么问题"排在"我做了什么"前面。面试官会向下一轮复制"这个人带着问题做系统"。
3. **主动报缺口**——"搜索、索引没有"必须自己先说。用"取舍"框架包装，把缺口变成成熟度信号，永远不要等对方用"和 Claude Code 比呢"来戳。
4. **结尾交出控制权**——"你想深挖哪一层？"暗示每层都敢接，同时是面试官水平的过滤器。
